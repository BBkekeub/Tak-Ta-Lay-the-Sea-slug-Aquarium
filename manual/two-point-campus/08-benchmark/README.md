# 08 — แผนทดสอบคอมสเปคต่ำ

## สถานะ

ยังไม่ได้รัน benchmark บนเครื่องสเปคต่ำหรือวัด Campus 1,000 คน ข้อมูลในหน้านี้คือแผนทดสอบ ไม่ใช่ผลทดสอบ CPU throttling ใน DevTools ใช้หาแนวโน้มได้แต่แทน Intel HD รุ่นเก่าหรือ bandwidth RAM ไม่ได้

## เครื่องฐาน

ตั้งเป้า i3-6006U + Intel HD Graphics 520, RAM 4GB, Windows/Chrome ที่ใช้งานได้ และพื้นที่วาด 1280×720 ที่ render scale 1 โดยรุ่น CPU/GPU ตรวจจาก [Intel](https://www.thailand.intel.com/content/www/th/th/products/sku/91157/intel-core-i36006u-processor-3m-cache-2-00-ghz/specifications.html) ส่วน RAM และพื้นที่วาดเป็นเงื่อนไขทดสอบที่เราเลือก ไม่ใช่ minimum requirement ของ Campus

เป้าหมายเริ่มต้น 30 FPS = งบประมาณ 33.3 ms ต่อเฟรม เป็นเป้าหมาย ไม่ใช่คำรับรอง ต้องบันทึก RAM แบบ single/dual channel, power mode, เสียบไฟหรือแบต, driver และความร้อนด้วย iGPU ใช้หน่วยความจำร่วมกับระบบ

## เมทริกซ์ฉาก

| ฉาก | จำนวนคน | จุดประสงค์ |
| --- | --- | --- |
| ร้านว่าง ไม่มีคน | 0 | ค่าใช้จ่ายพื้นฐานของฉาก |

ทุกฉากเทียบโมเดลเดิม, 5,000, และรุ่นลดรายละเอียด โดยวัสดุ เอฟเฟกต์ ตู้ ทาก เส้นทาง seed และตำแหน่งกล้องเหมือนกัน แยกคนที่จำลอง/อยู่ใน frustum/ส่งวาดจริงออกเป็นสามตัวเลข

## วิธีเก็บผล

warm-up 30 วินาที แล้วบันทึก 60 วินาทีอย่างน้อย 3 รอบ การโหลด shader และไฟล์ครั้งแรกให้รายงานแยก ไม่เอาไปปนค่า steady state หลีกเลี่ยงสลับ build แล้วใช้ฉากไม่เหมือนกัน

เก็บ frame interval p50/p95/p99, จำนวนเฟรมเกิน 50/100 ms, simulation ms, route queue age, pose ms, packing/upload ms, draw calls, uploaded bytes และ heap trend เวลา CPU รอบคำสั่ง WebGL ไม่ใช่เวลาทำงาน GPU จริง หากใช้ GPU timer query ต้องตรวจ availability/disjoint และไม่บล็อกอ่านผลทันที

เป้าหมายทดลอง: p95 ไม่เกิน 33.3 ms ที่ 30 FPS, ไม่มี stall เกิน 100 ms เกิดซ้ำจากระบบคน และ memory ไม่เพิ่มต่อเนื่องหลังเข้าออกหลายรอบ เกณฑ์นี้ทีมเลือกปรับได้ตามความรู้สึกเล่น ไม่ใช่มาตรฐาน Two Point
