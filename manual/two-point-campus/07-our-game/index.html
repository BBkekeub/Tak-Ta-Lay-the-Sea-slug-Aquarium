ทากทาเล · คู่มือวิจัย Two Point Campusตรวจหลักฐาน 19 กันยายน 2026 · ยังไม่มีผล benchmark 1,000 คน
Two Point Campus เพื่อพัฒนาเกมทากทาเล01 — หลักฐานจากเกมที่ติดตั้ง02 — ECS, Burst และงานหลายเธรด03 — การเดิน การหาทาง และฝูงคน04 — โมเดล กระดูก และแอนิเมชัน05 — การวาดภาพ Culling, LOD และ Batching06 — หน่วยความจำ Pool และเท็กซ์เจอร์07 — เปรียบเทียบและแผนพัฒนาเกมทากทาเล08 — แผนทดสอบคอมสเปคต่ำ09 — แหล่งข้อมูลและสิ่งที่ยังไม่รู้10 — สิ่งที่นำมาปรับได้ นอกเหนือจากลูกค้า11 — ตรวจงานคงเหลือหลังมีการปรับปรุงบางส่วน11 — ทำอะไรไปแล้ว เหลืออะไร

07 — เปรียบเทียบและแผนพัฒนาเกมทากทาเล

สถานะที่ตรวจจากโค้ด

ตรวจ working tree วันที่ 19 กันยายน 2026 ซึ่งมีงานแก้ไขเดิมอยู่แล้ว เก็บ hashes และตำแหน่งบรรทัดใน snapshot เลขบรรทัดอาจเปลี่ยนในอนาคต ให้ค้นชื่อฟังก์ชันด้วย

ระบบเกมเรามีแล้วสิ่งที่ควรทดลองต่อ
ภาพคนWebGL batching และ depthgeometry คงบน GPU, transform แทนสร้าง vertex arrays
ท่าทางแคช 12/30 Hzลด allocation ของ cached pose ที่เดิน
นอกจอpersonOnScreen และ loop หยุดวาดในฉากไม่ activeวัดจำนวน submissions ต้องเป็นศูนย์เมื่อไม่เห็น
ฝูงคนspatial grid และ route budget บางเส้นทางครอบคลุมจุดสแกนทั้ง PEOPLE และจัดคิว route รวม
เส้นทางgraph search จากมุมอุปสรรคแคช topology ตาม layout version
ฉากอื่นstepShopSimulation แยกจากวาดบางส่วนตรวจ timer throttling และความถูกต้องหลังสลับฉาก

ขนาดงานส่งข้อมูลปัจจุบัน

ใน paintPersonMesh หนึ่งสามเหลี่ยมถูกคลี่เป็น 3 vertices โดยแต่ละ vertex มี position 3 float และ color 3 float รวม 72 ไบต์ต่อสามเหลี่ยมก่อน blocker/glass

ถ้า 5,000 สามเหลี่ยมต่อคนถูกส่งทั้งหมด 100 คน จะเป็น 36 MB ต่อรอบวาด หรือ 1.08 GB/s ของปริมาณ payload เชิงคำนวณที่ 30 รอบต่อวินาที ตัวเลขนี้เป็นแบบจำลองจาก format buffer ไม่ใช่ bandwidth ที่วัดจริง ไม่รวมการคัดหน้าทิ้งและงานอื่น และไม่ได้แปลว่าถึงเพดานฮาร์ดแวร์แน่นอน

การคงเมชและสีร่วมไว้บน GPU จึงน่าทดลองก่อนลดโมเดล เพราะลดทั้งการเดินข้อมูลบน CPU และการอัปโหลดซ้ำ GPU skinning/rigid transforms ยังต้องวัดจำนวน bones และ shader cost ที่เพิ่ม

ลำดับงานที่แนะนำ

  1. เพิ่มตัววัดแยก simulation, route, pose generation, packing/upload และ draw พร้อม visible count
  2. ทำ baseline ฉากเดิมซ้ำ 3 รอบ บันทึก p50/p95/p99 และความถูกต้อง
  3. ลด allocation ใน cached moving pose และ reuse buffers โดยไม่เปลี่ยนรูปแบบโมเดล
  4. ทดลอง renderer ที่คง indexed geometry บน GPU และส่ง rigid-part transforms โดยเก็บ renderer เดิมไว้เทียบ
  5. แคช route graph และจัดคิวงานเมื่อ layout เปลี่ยน ใช้ spatial grid ในจุดที่วัดแล้วหนัก
  6. เพิ่ม LOD หรือ animation rate tiers เมื่อผลวัดชี้ว่าจำเป็น
  7. พิจารณา worker/instancing หลังเห็นคอขวดที่เหลือ ไม่เพิ่มเทคโนโลยีทุกอย่างพร้อมกัน

แต่ละขั้นต้องมีตัวเลือกย้อนกลับ เปลี่ยนทีละเรื่องเพื่อรู้ว่าเร็วขึ้นเพราะอะไร คู่มือนี้ยังไม่ได้ลงมือแก้ renderer

เงื่อนไขที่ห้ามเสีย

การบังหน้า/หลังตู้ กระจก เงา สี่มุมกล้อง การคลิกเลือกคน มือถือตู้และการเข้าคิวต้องเหมือนเดิม ลูกค้านอกจอไม่หยุดซื้อขาย การแพนและซูมต้องไม่ rebuild geometry คงที่ แคชมีเพดานและ release เมื่อเลิกใช้ ตาม AGENTS.md

ข้อสรุปต่อโมเดลใหม่

อนุญาตให้ทำต้นฉบับคนละ 5,000 สามเหลี่ยมเพื่อทดลองได้ แต่ยังไม่รับรองจำนวนคนหรือ FPS เก็บรุ่นลดรายละเอียดไว้เทียบภาพ ไม่ตัดรายละเอียดเพื่อชดเชยค่าใช้จ่ายของ renderer โดยไม่วัด
