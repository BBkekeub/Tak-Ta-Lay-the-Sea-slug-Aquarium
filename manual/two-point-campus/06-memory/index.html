06 — หน่วยความจำ Pool และเท็กซ์เจอร์

หลักฐานใน Campus

พบ CharacterPrefabPool, LevelPrefabPool, SharedPrefabPool และชื่อ pool อื่น ๆ ข้อมูลนี้สนับสนุนว่ามีโครงสร้าง reuse ออบเจ็กต์ แต่ไม่บอกว่าขนาด pool เท่าไร รีเซ็ตสถานะอะไร หรือเส้นทางใดเรียกใช้จริง

มี gc-max-time-slice=3 ใน boot.config บันทึกเป็นค่าจริงเท่านั้น ไม่สรุปว่าไม่มี GC pause เกิน 3 ms หรือว่า total GC cost ลดลงตามค่านี้

หลักฐานการปรับ texture และเอฟเฟกต์อยู่ใน แพตช์ทางการ จึงมองประสิทธิภาพรวมทั้ง CPU, GPU และ memory แทนใช้จำนวน polygon เป็นตัวแทนทุกอย่าง

คำนวณงบภาพอย่างไร

เท็กซ์เจอร์ RGBA8 แบบไม่บีบอัดขนาด 1024×1024 ใช้ข้อมูลฐาน 4 MiB; 512×512 ใช้ 1 MiB ถ้ามี mip chain ครบ ขนาดรวมเข้าใกล้ 4/3 เท่าของฐาน ตัวเลขนี้ไม่รวมสำเนาบน CPU, driver allocation และไม่ใช่ขนาดไฟล์ PNG

คน 100 คนที่อ้าง texture เดียวกันไม่จำเป็นต้องมี 100 สำเนา แต่หากสร้าง texture ใหม่ต่อคน memory จะต่างกันมาก แนวทางของเราคือใช้ palette/atlas ร่วมและส่งสีเฉพาะคน ขนาด atlas ที่ควรใช้ต้องดูความละเอียดจริงบนจอ

Pool ให้ถูก

pool เก็บออบเจ็กต์พร้อมใช้จึงลด churn แต่แลกกับ memory ที่ค้าง ต้องจำกัดเพดานและคืน resource เมื่อเลิกใช้ฉาก รีเซ็ต target, family, tradeOffer, route, animation state และ event listeners ไม่ให้ลูกค้าคนใหม่รับสถานะคนเก่า

สำหรับ typed arrays ควรขยายความจุเป็นขั้นแล้ว reuse โดยส่งเฉพาะช่วง active หลัง peak ฝูงใหญ่ไม่ควรปล่อยแคชสะสมไม่จำกัด ใช้เพดานและเงื่อนไขลดขนาดเมื่อสงบ หลีกเลี่ยงย่อขยายสลับทุกเฟรม

จุดวัดในเกมเรา

  • allocation ระหว่างคนเดิน เทียบยืนนิ่งและแพนกล้อง
  • heap ก่อนโหลด หลัง warm-up และหลังลูกค้าเข้าออกอย่างน้อย 10 รอบ
  • จำนวน geometry, texture และ buffer ที่ยังอยู่หลังเปลี่ยนฉาก
  • เวลา GC และ long frames ไม่ใช้ heap ขึ้นชั่วคราวเป็นหลักฐาน memory leak ทันที

ถ้า pooling ลด allocation แต่ทำให้สถานะปนกันถือว่าไม่ผ่าน แม้ FPS สูงขึ้น
