11 — ทำอะไรไปแล้ว เหลืออะไร

บันทึก 19 กันยายน 2026 · อัปเดตทุกครั้งที่ลงมือแก้จริง ไม่ใช่แผน

สรุปสั้น

เริ่มลงมือเฟส 1 ข้อแรกของ แผนในบท 07 แล้ว (เลิกสร้างเรขาคณิตคงที่ใหม่ทุกเฟรม) ยังไม่ได้ทำเฟส 0 (ตัววัดต่อเฟรม) ซึ่งเป็นตัวตัดสินงานที่เหลือทั้งหมด

ทำเสร็จแล้ว

แคชรูปทรงบัง/กระจกตู้ ไม่สร้างใหม่ทุกเฟรม

ปัญหาเดิม: ทุกเฟรมที่มีการวาดคน paintPersonMesh จะสร้างอาร์เรย์ใหม่ทั้งชุด — หน้าตัดทึบของเฟอร์นิเจอร์ทุกชิ้น (ชิ้นละ 5 หน้า × 4 จุด) และกระจกตู้ทุกใบ (ใบละ 3 บาน) ทั้งที่รูปทรงพวกนี้เปลี่ยนเฉพาะตอนวาง ย้าย หมุน หรือเก็บของ ไม่ได้เปลี่ยนตอนแพน/ซูม

ที่แก้:

  • js/people.js — เพิ่ม layoutSignature(), objGeometry(o), syncGeoCache() แคชรูปทรงต่อชิ้น

ทิ้งแคชทั้งชุดเมื่อลายเซ็น layout เปลี่ยน แล้วสร้างใหม่แบบขี้เกียจตอนถูกขอ

  • js/people.js — ลูปสร้างกระจกตู้ใน paintPersonMesh เปลี่ยนไปหยิบจากแคช
  • js/cat-seller.js — **จุดสำคัญ** ไฟล์นี้เขียนทับ personFurnitureFaces ของ people.js (โหลดทีหลัง)

แคชใน people.js จึงไม่มีผลกับเส้นทางจริง ต้องใส่แคชในตัวที่เขียนทับด้วย เก็บโค้ดเดิมไว้ชื่อ _personFurnitureFacesUncached เพื่อเทียบผลลัพธ์

  • js/people.js — window.PeoplePerf สำหรับตรวจ: geoBuilds, geoCached, counts()

ข้อสรุปตรงไปตรงมา: กำไรที่วัดได้จริงคือ **ลดขยะ (allocation) ไม่ใช่เวลาเฉลี่ย** ร้านใหญ่ยังเสียเวลาไปกับการ push ตัวชี้ ~150 ก้อนต่อเฟรม บวกการสแกนลายเซ็น layout ผลของการลดขยะจะไปโผล่ที่ GC และเฟรมกระตุก ซึ่ง micro-benchmark นี้วัดไม่ได้ **ต้องรอเฟส 0 ถึงจะรู้ว่าคุ้มแค่ไหน** อย่าเพิ่งเคลมว่าเร็วขึ้น

เหลืออะไร (ตามลำดับที่ควรทำ)

เฟส 0 — ตัววัด (ยังไม่เริ่ม · ต้องทำก่อนทุกอย่างที่เหลือ)

  • js/perf.js วัดเวลาแยก sim / route / pose / pack+upload / draw / composite
  • ตัวนับสามตัวตามบท 08: จำลองกี่คน / อยู่ในจอกี่คน / ส่งวาดจริงกี่คน + triangles + bytes
  • สรุป p50/p95/p99 บนหน้าต่างเลื่อน + นับเฟรมเกิน 50/100 ms
  • ตัวสร้างฉากทดสอบซ้ำได้ (เสกลูกค้า N คน seed คงที่ กล้องตำแหน่งเดิม) ตามเมทริกซ์บท 08
  • เกณฑ์เสร็จ: รันเมทริกซ์ฉากแล้วกรอกตารางผลในบท 08 ได้

เฟส 1 — ที่เหลือ

  • reuse typed array ใน paintPersonMesh แทน subarray ใหม่ทุกเฟรม + เลิก map faces/vertices ตอนคนเดิน
  • **เซฟ**: วัด stringify / sign / write แยกกัน (รู้แล้วว่า sign ≈ 9.5 ms ต่อ 1 MB และระหว่างแข่งเซฟทุก 1 วินาที)

ถ้าพบ spike ให้แยกสถานะร้อน (เงิน/ซื้อขาย) ออกจากสถานะที่เปลี่ยนตลอด (ตำแหน่ง) + debounce

  • render scale: ตอนนี้ล็อก min(2, devicePixelRatio) ทำเป็น preset ให้เลือก 1 ได้

เฟส 2 — renderer (หลังมีตัวเลขเท่านั้น)

คง indexed geometry บน GPU ส่งเฉพาะ transform ต่อคน/ต่อชิ้น เริ่มจาก rigid-part ก่อน weighted skinning ต้องมีสวิตช์สลับกลับ renderer เดิม และตรวจภาพสี่มุมกล้อง กระจก เงา และ hit test

เฟส 3 — เส้นทาง/ฝูงคน

แคชกราฟพื้นร้านตาม layoutVersion · คิวคำขอเส้นทางรวมพร้อมงบเวลาและอายุคำขอ · เปลี่ยน PEOPLE.filter().sort() ที่เหลือให้ใช้ spatial grid ที่มีอยู่แล้ว

เฟส 4 — LOD

ตามขนาดบนจอ + hysteresis · ลอง 5,000 / 2,500 / 1,000 เหลี่ยม **เฉพาะเมื่อผลวัดชี้ว่า vertex เป็นคอขวดจริง** ถ้าคอขวดคือ overdraw ของกระจก การลดเหลี่ยมไม่ช่วย

ยังไม่ทำ

ECS · Web Worker · baked animation texture · โมเดล 5,000 เหลี่ยม — รอตัวเลขจากเฟส 0

บริบทที่เปลี่ยนไปในวันเดียวกัน (สำคัญต่อเป้าหมายทดสอบ)

ระบบลูกค้าถูกแก้วันนี้ ทำให้จำนวนคนในร้านสูงขึ้นกว่าเดิมมาก จึงต้องวัดที่ตัวเลขใหม่นี้ก่อนไปไล่ 100–200 คน

  • ลูกค้าเดิมตันที่ ~2 คนตลอดเกม → ตอนนี้ผูกกับความนิยมแบบชันขึ้นเรื่อย ๆ (ความนิยม 70 = 10 คน · 3,000 = 51 คน)
  • ความจุพื้นที่ 1 คน/4 ช่อง → 1 คน/3 ช่อง (ร้านเริ่มต้น 48 ช่อง = 16 คน)
  • นักแข่ง (เพดาน 10) และพ่อค้า (เพดาน 2) แยกโควตาออกจากลูกค้าแล้ว ไม่แย่งที่กัน
  • รวมแล้วร้านมีคนพร้อมกันได้ถึง **28 คนในการเล่นปกติ** ซึ่งเกินช่วง "20–30 คน" ที่บท 07 บอกว่ายังไม่มี benchmark รองรับ

ฉากทดสอบแรกของเฟส 0 จึงควรเป็น **28 คนในร้านจริง** ไม่ใช่เริ่มที่ 100 คน
