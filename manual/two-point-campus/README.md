# คู่มือศึกษา Two Point Campus เพื่อพัฒนาเกมทากทาเล

ตรวจสอบ 19 กันยายน 2026 · เกมในเครื่องเวอร์ชัน 10.3.169253+2024-12-06.1241

เปิดหน้าอ่านคู่มือด้วย [index.html](index.html) ได้โดยตรง ไม่ต้องเปิดเซิร์ฟเวอร์ คู่มือนี้ศึกษาระบบประสิทธิภาพของ Campus เพื่อวางแผนรองรับลูกค้าจำนวนมากในเกมทากทาเล ไม่ใช่คู่มือเล่นเกม และไม่เหมารวมถึง Hospital หรือ Museum

## ข้อสรุปที่ใช้ตัดสินใจได้

Campus มีหลักฐานทั้งจากไฟล์ติดตั้งและผู้พัฒนาว่าใช้หลายวิธีร่วมกัน ได้แก่ ECS/Burst, render jobs, GPU skinning, การปรับงานแสดงผลตามขนาดบนจอ และการลดภาระวัสดุ/เท็กซ์เจอร์ ส่วนจำนวนสามเหลี่ยมตัวละครจริงและผลทดสอบ 1,000 คนยังไม่ทราบ

เกมเรามี batching, culling, แคชท่าทาง และ spatial grid อยู่แล้ว แต่ยังแปลงพิกัดและประกอบข้อมูลหน้าสามเหลี่ยมบน JavaScript ก่อนอัปโหลด GPU ในแต่ละรอบวาด งานนี้ควรวัดและลดก่อนตัดสินว่าโมเดลคนละ 5,000 สามเหลี่ยมหนักเกินไป

คำประเมินเดิมว่า 20–30 คนเริ่มไม่ไหวเป็นความเห็นที่ยังไม่มี benchmark รองรับ จึงไม่ใช้เป็นข้อจำกัดในคู่มือนี้

## วิธีอ่านความน่าเชื่อถือ

- ยืนยันจากไฟล์: อ่านข้อมูลหรือค่าจริงจากเกมที่ติดตั้ง แต่ชื่อคลาสอย่างเดียวไม่ยืนยันวิธีทำงาน
- ผู้พัฒนายืนยัน: เอกสารจาก Two Point หรือ Unity ที่กล่าวถึง Campus โดยตรง
- อนุมาน: แนวคิดที่สอดคล้องกับหลักฐาน แต่ยังไม่เห็น implementation หรือผล runtime
- ข้อเสนอสำหรับเรา: แนวทางออกแบบใหม่ ไม่ใช่คำกล่าวว่า Campus ทำเช่นนั้นแน่นอน

## อัปเดตหลักฐาน

รันจากรากโปรเจกต์: `node manual/two-point-campus/tools/collect-evidence.mjs`

สคริปต์อ่านไฟล์ติดตั้งอย่างเดียวและเขียนผลลง evidence ภายในคู่มือ มี SHA-256 สำหรับตรวจว่าบิลด์เปลี่ยนหรือไม่ ไม่คัดลอกโมเดล เท็กซ์เจอร์ เซฟ หรือไบนารีของ Two Point มาลงโปรเจกต์

หลังแก้ Markdown รัน `node manual/two-point-campus/tools/build-guide.mjs` เพื่อสร้างหน้า HTML ใหม่ เอกสารชุดนี้ไม่เปลี่ยนระบบเกมหรือการเซฟ
